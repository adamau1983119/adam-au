# 🔬 WTS灵签APP智能邮件通知系统

## 概述

为了避免管理者收到过多邮件，我们实现了一个**智能邮件通知系统**，该系统采用多层过滤和聚合机制，只在系统真正出现问题时才发送邮件通知。

## 🛡️ 智能过滤策略

### 1. **频率控制**
- **最小邮件间隔**: 2小时（从原来的30分钟增加到120分钟）
- **目的**: 防止短时间内发送过多邮件
- **实现**: 基于时间戳的频率控制机制

### 2. **严重程度分级**
| 严重程度 | 发送条件 | 触发阈值 |
|---------|---------|---------|
| **LOW** | ❌ 永不发送 | - |
| **MEDIUM** | ⚠️ 仅在持续恶化时发送 | 健康评分持续下降且低于75分 |
| **HIGH** | ⚠️ 聚合后发送 | 1小时内5个或以上高严重错误 |
| **CRITICAL** | 🚨 聚合后发送 | 30分钟内3个或以上严重错误 |

### 3. **错误聚合机制**
- **时间窗口**: 30分钟内相同类型的错误会被聚合
- **重复抑制**: 相同错误60分钟内不重复发送
- **智能计数**: 只计算活跃的、未解决的错误

### 4. **性能趋势分析**
- **监控指标**: 基于30分钟时间窗口的性能趋势
- **触发条件**: 性能下降超过20%且持续恶化
- **重复控制**: 相同性能问题60分钟内不重复告警

### 5. **健康评分监控**
- **评估周期**: 基于最近5次健康检查
- **触发条件**: 健康评分下降超过15分且平均分低于80
- **渐进式响应**: 只在显著恶化时才发送通知

## 📧 邮件类型和发送策略

### 1. **紧急错误聚合邮件**
- **触发条件**: 30分钟内出现3个或以上严重错误
- **收件人**: 管理员邮箱（admin@wts-app.com, support@wts-app.com）
- **内容**: 聚合的错误统计、时间分布、影响分析
- **频率**: 满足条件时立即发送，之后重置计数器

### 2. **系统健康异常邮件**
- **触发条件**: 健康评分显著下降且持续恶化
- **收件人**: 开发者邮箱（dev@wts-app.com）
- **内容**: 健康评分变化趋势、系统资源状态、建议行动
- **频率**: 基于健康评分变化趋势，最少间隔2小时

### 3. **性能持续下降邮件**
- **触发条件**: 特定操作性能持续下降超过20%
- **收件人**: 开发者邮箱（dev@wts-app.com）
- **内容**: 性能指标对比、趋势分析、优化建议
- **频率**: 基于性能趋势，最少间隔2小时

## 🔄 工作流程示意

```
错误发生 → 智能评估 → 聚合分析 → 条件判断 → 发送邮件
    ↓           ↓           ↓           ↓           ↓
不发送     继续聚合     继续聚合     继续聚合     发送邮件
```

### 具体流程：

1. **错误发生时**:
   - 立即记录错误到本地聚合器
   - 更新错误计数和时间戳
   - 评估是否满足发送条件

2. **聚合分析阶段**:
   - 相同类型错误计数累加
   - 记录首次和最近发生时间
   - 保留最近10个错误样本

3. **条件判断阶段**:
   - 检查严重程度阈值
   - 验证时间窗口限制
   - 确认不是重复通知

4. **发送决策**:
   - 满足条件 → 发送聚合邮件
   - 不满足条件 → 继续监控

5. **发送后处理**:
   - 重置相关聚合计数器
   - 记录通知历史
   - 更新频率控制时间戳

## 🔧 故障排除

### 邮件发送失败
1. **检查网络连接**: 确保设备有网络访问权限
2. **验证邮件配置**: 确认SMTP服务器设置正确
3. **查看本地日志**: 检查WorkManager执行状态
4. **检查权限**: 确保应用有网络权限

### 过滤过于严格
1. **调整阈值**: 根据实际运营情况降低触发条件
2. **修改时间窗口**: 扩大聚合时间窗口
3. **增加严重程度**: 允许更多级别错误触发邮件

### 过滤不够严格
1. **提高阈值**: 增加错误数量要求
2. **缩短时间窗口**: 减少聚合时间范围
3. **降低严重程度**: 只对更严重错误发送邮件
