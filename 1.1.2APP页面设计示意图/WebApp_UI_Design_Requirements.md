# WebApp UI 設計需求文件

## 📱 DS黃大仙靈籤 App - AI Agent WebApp 介面設計

### 🎯 專案概述
**專案名稱：** AI Agent WebApp 管理介面  
**目標平台：** 跨裝置 WebApp (手機/平板/桌面)  
**主要功能：** 多 App 管理、AI Agent 模組化執行、行銷推廣整合  
**技術架構：** 模組化 AI Agent + Web UI + Google Search Console 整合

### 🚨 WebApp 開發四大核心要點（永遠第一優先）

#### 1. 使用者體驗 (UX) - 永遠第一優先
- **載入體驗**：骨架屏 + 進度指示，避免空白頁面
- **錯誤處理**：使用者友善的錯誤訊息 + 解決建議
- **操作回饋**：即時視覺回饋 + 成功確認
- **流程設計**：任務導向，避免功能導向的複雜流程

#### 2. 跨裝置適配 (Responsive Design) - 市場現實
- **Mobile First**：手機優先設計原則
- **觸控優化**：按鈕最小44px，間距8px
- **內容優先**：重要資訊優先顯示
- **載入優化**：圖片懶加載，代碼分割

#### 3. 資料安全與維護性 - 長期成功關鍵
- **前端安全**：敏感資料不暴露，XSS防護
- **API安全**：JWT認證，HTTPS傳輸
- **權限控制**：基於角色的存取控制
- **隱私保護**：最小資料收集原則

#### 4. 維護性 - 可持續發展基礎
- **模組化設計**：功能模組獨立，易於維護
- **組件化UI**：可重用組件，降低維護成本
- **文檔完整**：API文檔、使用指南
- **監控機制**：錯誤追蹤，效能監控

## 🧠 AI Agent 設計原則

### 核心設計理念
**使用者友善優先 + 靈活的反思型提示詞技巧**

#### 反思型提示詞框架
1. **思維鏈 + 假設推理**
   - 引導 AI 展開「問題 → 解法 → 評估 → 選擇」的推理過程
   - 避免直接跳到結論，確保思考過程透明化

2. **反思 + 自我驗證**
   - 促使 AI 進行「自我批判」和盲點檢查
   - 提升建議的可信度和準確性

3. **比較分析 + 案例類比**
   - 調用知識庫中的案例進行類比推理
   - 更貼近真實世界的思考方式

#### 分層提示詞系統
- **簡單問題** → 使用「思維鏈」技巧
- **複雜決策** → 使用「反思 + 自我驗證」
- **創意發想** → 使用「比較分析 + 案例類比」

#### 使用者控制權設計
- 預設為簡單模式，讓使用者主動選擇深度思考
- 提供多種「思考模式」選項
- 在回應中說明使用的思考方法，促進學習

## 🎨 介面設計規範

### 1. 資訊架構設計

#### 層次化呈現邏輯
```
App 選擇 → 模組選擇 → 任務執行 → 結果回報
```

#### 認知負荷控制
- 每個階段只顯示相關資訊，避免資訊過載
- 使用卡片式設計引導使用者注意力流向
- 重要資訊優先顯示，次要資訊摺疊處理

### 2. 互動模式設計

#### 對話式引導
- 模擬真人顧問的互動方式，降低學習成本
- 使用 Chat bubble 風格，左側為 Agent 回應，右側為使用者選項

#### 確認機制
- 高風險操作需要二次確認，提升安全感
- 顯示模擬預覽與風險評估
- 提供「批准執行」「調整建議」選項

#### 即時回饋
- 每個操作都有明確的視覺回饋
- 任務執行後回報成果摘要（例如：CTR 提升 12%、CPI 降低 18%）

## 📱 響應式設計規範

### 跨裝置適配策略（四大要點實現）

#### 手機版 (320px - 768px) - Mobile First 優先
- **佈局**：單欄佈局，模組卡片垂直堆疊
- **導航**：底部導航欄 + 漢堡選單
- **互動**：大按鈕設計（最小44px），適合觸控操作
- **載入優化**：骨架屏 + 圖片懶加載
- **內容優先**：重要資訊優先顯示，次要資訊摺疊

#### 平板版 (768px - 1024px) - 觸控與滑鼠並重
- **佈局**：雙欄佈局，左側 App 列表，右側模組選擇
- **導航**：側邊欄導航 + 頂部工具欄
- **互動**：中等按鈕尺寸，支援觸控和滑鼠
- **間距設計**：8px網格系統，確保觸控舒適度
- **載入策略**：預載入常用模組，提升使用體驗

#### 桌面版 (1024px+) - 效率與功能並重
- **佈局**：三欄佈局，增加「快速操作面板」
- **導航**：頂部導航欄 + 側邊欄
- **互動**：小按鈕設計，支援鍵盤快捷鍵
- **多視窗支援**：支援多個App同時管理
- **鍵盤導航**：Tab順序邏輯，Enter確認操作

### 技術實現（維護性優先）
- **CSS架構**：使用 CSS Flexbox 或 Grid + Media Queries
- **容器查詢**：採用「容器查詢（Container Queries）」而非僅依賴視窗寬度
- **彈性單位**：使用彈性單位（vw/vh, %, rem）而非固定寬度（px）
- **組件化**：可重用組件，降低維護成本
- **文檔化**：每個組件都有使用文檔和範例

## 🎨 視覺設計規範

### 1. 視覺層次與資訊密度

#### 卡片設計
- **陰影效果**：使用「卡片陰影 + 懸停效果」建立層次感
- **間距系統**：採用「8px 網格系統」統一間距
- **圓角設計**：統一使用 8px 圓角，提升現代感

#### 色彩層次
- **重要資訊**：使用「高對比色彩」突出（如 CTR 提升 12%）
- **次要資訊**：使用「灰色調」降低視覺權重
- **狀態色彩**：
  - 成功狀態：生機綠色 (#10B981)
  - 錯誤狀態：警示橙色 (#F59E0B)
  - 警告狀態：警示紅色 (#EF4444)
  - 資訊狀態：專業藍色 (#3B82F6)

### 2. 微互動與動畫設計

#### 載入狀態
- **骨架屏**：使用 Skeleton Screen 而非旋轉圖標
- **載入動畫**：淡入效果，時長 200-300ms

#### 操作回饋
- **成功回饋**：綠色勾選動畫 + 輕微震動效果
- **錯誤狀態**：紅色搖擺動畫 + 錯誤圖標
- **頁面轉換**：使用「淡入淡出」而非硬切換

#### 動畫時長
- 微互動：200-300ms
- 頁面轉換：300-500ms
- 複雜動畫：500-800ms

## 🔐 資料安全與授權機制（四大要點實現）

### 登入與授權（使用者體驗優先）
- **OAuth 2.0**：支援 Google、Facebook 等第三方登入
- **JWT Token**：用於 API 授權和會話管理
- **權限控制**：基於角色的存取控制（RBAC）
- **使用者友善**：登入流程簡化，錯誤訊息清晰

### 資料保護（安全第一）
- **前端安全**：敏感資料不暴露在前端，XSS防護
- **API 安全**：所有 API 呼叫需要授權驗證，HTTPS傳輸
- **資料加密**：敏感資料使用 HTTPS 傳輸，資料庫加密
- **隱私保護**：最小資料收集原則，使用者同意機制

### 高風險操作控管（維護性考量）
- **二次確認**：API 提交、廣告投放等操作需要確認
- **權限檢查**：操作前檢查使用者權限
- **操作記錄**：記錄所有敏感操作，便於審計
- **錯誤處理**：友善的錯誤訊息，提供解決建議

### 跨裝置安全適配
- **行動裝置**：生物識別登入，安全儲存
- **桌面裝置**：密碼管理器整合，安全鍵盤
- **平板裝置**：混合認證方式，適應使用場景
- **統一安全**：所有裝置使用相同的安全標準
